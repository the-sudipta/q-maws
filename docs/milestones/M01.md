# M1: Engine skeleton — checkpoints, progress, terminal display, basic CI

Status: **complete, approved by the owner on 2026-10-02**, tagged `v0.1-m01-engine` (on commit `1018bf3`).

## What was built

- **Run engine** (`crates/qmaws-engine`): run folders with the full layout; `run.json` with stage states (`pending`, `running`, `done`), output hashes, the frozen chunk plan, measured throughput, accumulated working time and the last interface; atomic writes with SHA-256 hash files; resume that verifies inputs, removes interrupted writes, resets missing or damaged units and continues with the first unfinished one.
- **Chunk plan** from a calibration micro-benchmark (about 0.25 s) and a target chunk duration (default 3 s), frozen in `run.json`.
- **Root fingerprint** independent of chunk boundaries (decision recorded as OI-4 in `docs/OPEN_ISSUES.md`).
- **Progress events and estimates:** `Started`, `Progress`, `Log`, `Finished`, `Stopped`; per-stage cost model with moving-average throughput (weight 0.3); overall progress weighted by estimated cost.
- **Terminal display** (`crates/qmaws-tui`): overall bar and stage bar with stage number, elapsed and remaining time and the current item, log lines above; plain lines when the output is not a terminal; `--quiet`, `--json-progress`, `--no-color`.
- **Commands** (`crates/qmaws-cli`): `qmaws toy-run`, `qmaws resume`; Ctrl+C stops cleanly, a second Ctrl+C exits at once; exit status 3 for a resumable stop.
- **Toy stage:** SplitMix64 block sums in chunks, with final outputs `audit/chunks.json`, `audit/root.txt`, `report/toy_result.json`.
- **Continuous integration** (`.github/workflows/ci.yml`) on Windows, macOS and Linux, and a dependency license check with `cargo deny` (`deny.toml`).
- **Dependencies:** serde, serde_json, sha2, indicatif, clap, ctrlc; 52 crates in total for the release platforms, all under allowed licenses (`docs/DEPENDENCIES.md`, `THIRD_PARTY_NOTICES`).

The first CI run (36971678983, commit `0b92934`) passed all build and test jobs but failed the dependency job, because cargo deny counted the path dependencies between workspace crates as wildcards. Reproduced locally and fixed in `1807d39` (`allow-wildcard-paths = true`).

A real defect was found while writing the kill test and fixed before commit: a kill between the rename of `run.json` and the write of its hash file left a run that could not be resumed. A complete `run.json` with a missing hash file is now accepted (the rename is atomic); a hash file that does not match is still refused. A unit test covers it.

## Known limitations

- **Calibration overestimates sustained speed on this laptop.** The 0.25 s calibration runs at the processor's short-term peak speed. In the default toy run, throughput fell to about half after the first chunk, so chunks took about 6.2 s instead of the 3 s target (the target range is 2 to 5 s), and the remaining-time estimate lagged: 9.9 s into the run it showed 17.0 s remaining while 28.6 s remained. The estimate converges by the end of the run. Possible improvements for a later milestone: a longer calibration, a higher weight for recent measurements, or adapting the target per stage. Not changed in M1 without the owner's view.
- Chunks run one at a time on one core; parallel processing comes with the real stages.
- No lock prevents two processes from resuming the same run at the same time.
- The progress bars were not inspected on an interactive terminal; plain and JSON output were checked, and the bars are drawn by `indicatif`.
- Without arguments `qmaws` prints its help; the interactive menu comes later.
- The toy run is the only kind of run.
