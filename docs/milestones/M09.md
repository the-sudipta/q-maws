# M9: GUI

Status: **complete, awaiting the owner's approval**.

## What was built

- **Pause and live events** (`qmaws-engine::progress`): the interface can ask the engine to pause between units of work (taxa, chunks, bootstrap replicates); the pause is not counted as working time and Stop still works during it. New events `Quartet` (the last quartet of each weighing chunk, for the live worksheet) and `Provisional` (each provisional tree).
- **Live provisional tree** (plan 4.7, `qmaws-engine::provisional`): every 5% of the quartets or 3 minutes, the finished quartets are amalgamated, provisional halo values computed and the tree drawn with a `PROVISIONAL — <x>% of quartets` watermark to `figures/live/halo_tree_latest.svg/.png/.pdf`, with 480-pixel frames in `work/provisional/frames/`; an update over 10% of its interval doubles both intervals (logged); state saved for resume; `report/convergence.csv` gives each provisional tree's nRF to the final tree; `--no-live-tree`. The figure is the basic one agreed for M9: circular cladogram (`qmaws-viz::tree`, midpoint display root), label ring, halo ring with legend, watermark.
- **Shared menu logic** (`qmaws-engine::launch`): settings, new run requests, review text, runs on this computer with their percentage done and last interface, the unfinished run with the same data and settings, the user configuration file with extra results folders and the resume queue; a CPU core limit per session.
- **Terminal menu** (`qmaws-tui::menu`, `qmaws menu`, started by `run.bat` and `run.sh` without arguments): the main menu of plan 5.2 with the wording of the plan, `0. Back` in every submenu; the program carries out the choice in the interface chosen and, after a single resumed run, offers the next unfinished run.
- **GUI** (`qmaws-gui`, `qmaws gui`): `eframe`/`egui` window with the menu as tabs; for a new run the steps Data → Reference → Output → Settings → Review → Run; the resume list (single run, all runs, the saved queue); the verify screen with the four types; during a run the live Halo Tree with zoom and pan and changed branches highlighted, the final tree at the end, the live worksheet (taxa, 16 counts, W1, W2 log-likelihoods, weights), the stage log, overall and stage progress, elapsed and remaining time, Pause/Continue and Stop, "Resume here" after a stop. Unfinished runs are offered on launch. Light and dark themes, text size buttons. The engine runs in a worker thread (`controller.rs`); the window never blocks.
- **Commands:** `qmaws menu`, `qmaws gui`, `--gui` / `--terminal` on `run` and `resume` (default terminal), `qmaws resume --all` (saved queue, continued after a stop), `qmaws verify --quick`; `qmaws resume` without `--output` also looks in remembered results folders.
- **Licenses:** egui's built-in fonts are off (no font files ship; a system font is loaded at start); BSL-1.0 allowed for `clipboard-win` and `error-code` (owner's decision). 378 crates for the release platforms (183 before), all listed in `THIRD_PARTY_NOTICES`.
- Documentation: README ("GUI mode", "Terminal mode"), `docs/USER_GUIDE.md` (menu, GUI, live tree, pause and switching), `docs/DESIGN.md` (pause, live tree, menu and launch, GUI), `docs/DEPENDENCIES.md`, crate READMEs.

## Known limitations

- There is no native "Browse" button: paths are typed, pasted or dropped onto the window. A file dialog crate (`rfd`) would bring in GTK or the desktop portal stack on Linux.
- The window was tried on Windows only; macOS and Linux build in CI but were not opened. The window needs OpenGL 2 or later and an installed font; without a font it says so and the terminal mode remains.
- The terminal menu was tested with scripted answers, not typed in an interactive terminal in this session.
- Final figures without watermark, the growth animation `figures/halo_tree_growth.gif`, group bands and support colours are M10 (owner's decision for the M9 figure scope).
- Reference trees are checked for matching names but not used for comparisons yet (M11); downloading from the Open Tree of Life is not implemented (the menu says so).
- The engine still refuses inputs with warnings, so the menu shows each warning and offers only another folder or back.
- `cores` and the memory limit apply to one session and are not stored; a resumed run uses all cores.
- Closing the window during a run waits for the current unit of work (a chunk of about 3 s) before it closes.
- Ctrl+C at a menu prompt in the terminal sets the stop flag; the menu then ends after the current action, and a second Ctrl+C exits at once.
